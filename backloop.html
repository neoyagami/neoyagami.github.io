Backloop

A bridge from physical PipeWire video sources to dedicated V4L2 virtual devices on Linux.

How it worksSetupDaily useFull guides

One source, the right route for each app.

PipeWire opens the physical capture device and distributes its frames. Backloop receives a PipeWire link, converts the video with GStreamer, and writes to a dedicated /dev/video* loopback device. WirePlumber rules keep these virtual outputs out of PipeWire to prevent feedback loops.

PipeWire-aware apps

Select the original physical source through PipeWire. These apps receive video directly from the PipeWire graph.

V4L2-only apps

Select the assigned Backloop … device. Give each independently negotiating application a separate endpoint.

For example, OBS can use the original PipeWire source while Discord uses a Backloop endpoint. Sharing happens in PipeWire: opening the same V4L2 endpoint from multiple apps can still cause format or buffer conflicts.

Read the architecture and sharing model for the full explanation.

Getting started

The upstream installation guide targets mutable Fedora systems with RPM Fusion enabled. It requires PipeWire, WirePlumber, GStreamer, V4L2 utilities, and the v4l2loopback kernel module. Podman builds the executable in a container; video processing runs on the host.

  1. Follow the host requirements and let the loopback kernel module finish building.
  2. Use the build and installation instructions to install the system and user services. The user installation restarts WirePlumber to activate the anti-feedback rule.
  3. Find physical sources with backloop sources, then configure channels in /etc/backloop/config.yaml. Each source filter must identify one distinct physical PipeWire source. Device labels must start with Backloop .
  4. Enable the configured channel services and select the appropriate sources in your applications.

Each channel can set its resolution, frame rate, pixel format, thread count, and retry behavior. Automatic device allocation starts at /dev/video42 and skips devices already in use. See the configuration reference and channel management guide before adding or changing channels.

Daily operation

After installation and configuration, list sources and channels:

backloop sources
backloop channels

Replace source1 below with your configured channel name. Enable its service, check the bridge, and follow its logs:

systemctl --user enable --now backloop@source1.service
backloop check source1
systemctl --user status backloop@source1.service
journalctl --user -u backloop@source1.service -f

Restart an individual bridge without restarting PipeWire or your browser:

systemctl --user restart backloop@source1.service

Stop a channel and disable its automatic startup:

systemctl --user disable --now backloop@source1.service

Stopping a bridge leaves its virtual device visible without a producer. Loopback devices are managed separately by the system service. For missing sources, device conflicts, or signal issues, use the troubleshooting guide.
